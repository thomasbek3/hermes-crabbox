# Provider executor composition

ProviderExecutor is a trusted worker callback for WorkerDispatcher.execute_request. The controller supplies the exact account reservation, execution grant, immutable AttemptBinding, qualified PinnedCLI profile and remaining-root-budget reader. It verifies current durable grant and attempt/generation, checks the authenticated payload digest, admits the native Hermes request through the bounded codec, and sends only canonical transcript bytes to ProviderDispatch with the same64hex nonce.

Normal sequence is admit, launch, collect, cleanup, deliver, strict bootstrap-envelope parse, codec encode. Successful codec output requires the actual requested pinned identity and existing tool-schema validation. A durable cleaned/delivered result can be retrieved again; unknown or in-flight dispatch is never restarted. Cleanup failure cannot return provider success or authorize credential reuse. Account ownership remains reserved between requests. Provider body/error prose is not forwarded on unrecognized failures.

The callback itself does not grant root ancestry, provider entitlement or activation. It still requires atomic root policy admission in ProviderDispatch, a controller cancellation observer during blocking Docker calls, actual adapter qualification, and account quarantine on authentication rejection. Cancellation observed between phases revokes the grant; this is not a claim of250ms supervision while runtime.start blocks. Protocol metadata continues to distinguish worker-reported model/usage from provider-verified billing/identity.

Tests compose actual Store/ProviderLeases/ProviderDispatch/codec with synthetic runtime effects. They do not qualify Docker or real authentication. Fable checkpoint is recorded in reviews/provider-executor-fable.md and its receipt; integration stays unactivated until review disposition and remaining gates are complete.
