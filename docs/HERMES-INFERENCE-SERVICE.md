# Private inference HTTP boundary

`InferenceService` exposes one `/v1/chat/completions` request per connection. The controller supplies a SHA256 digest of a random 256-bit execution capability, a trusted current-authorization callback, and an execution callback. The service never loads provider credentials, issues grants, chooses models or executes tools. Local tests bind loopback. Production must bind only inside the isolated provider network without publishing a host port; no deployment is currently configured.

Execution callback composition is: revalidate the controller execution grant and immutable profile under the account reservation transaction; acquire an exclusive inference/refresh lease; admit the codec request; create a fresh one-shot transport inside the qualified provider boundary; execute; prove outer container/process cleanup before releasing ownership; encode the result. Protocol admission should precede expensive resource creation. The HTTP capability is not a provider token. The initial authorization check is only an early refusal; callback admission must recheck after the body is read, since revocation can race any request.

The listener is deliberately serial. Header/socket inactivity timeout defaults to2s, total header/body deadline5s, write timeout5s, body cap256KiB, response cap2MiB. It rejects duplicate JSON keys, nonfinite values, duplicate content lengths and transfer encoding. No default request or exception logs are emitted. An optional event callback receives only fixed status/code pairs. Responses are buffered; SSE encoding does not imply streaming inference. Request/response limits are not provider resource quotas.

Disconnect or execution deadline signals the callback cancellation event. Python cannot forcibly terminate an uncooperative callback. The outer supervisor must terminate/quarantine the service and its provider processes without releasing leases merely because120s elapsed. A separate timer shuts down the connection at the total header/body deadline. Listener remains serial; rate admission and outer supervision remain controller responsibilities. Client write-half-close is treated as cancellation; the qualified SDK must not use write-half-close while awaiting a response. Additional bytes arriving on the socket cancel execution; bytes already buffered by HTTP parsing may instead be discarded when this one-request connection closes. Oversized rejected bodies drain at most1MiB/100ms after response; larger or slower uploads can still receive a reset, not guaranteed413 delivery.

Nineteen local service/codec tests cover successful SSE, reauthorization after revocation, wrong capability, malformed JSON/size caps, fixed failure output, disconnect cancellation, invalid/oversized executor output and execution deadline signaling. A two-request HTTP/codec/synthetic CLI tool-result roundtrip passes. This is not native Hermes execution. Concurrent revocation/account lease, Linux fixed-port restart, slow response-reader behavior, restart/container cleanup and real Hermes/provider requests remain unverified. Fable returned REVISE; independent corrections/disposition recorded, no repeat PASS sought. No live services changed.
