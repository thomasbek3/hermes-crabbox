# Bounded prior-stage context

`load_stage_context(scheduler, child_id, *, expected_generation, forbidden_values)` returns immutable `StageContext(canonical_json, text, digest, assignment_sha256, input_revision_sha256)`. The text explicitly marks the contents as untrusted evidence, never instructions, tool permissions, verification authority or workflow policy.

The loader validates the frozen broker reference array (exact artifact ID/hash fields, ordered, unique, at most 32), current preparing child authority, owner/project/session/turn/root/generation, cancellation, client revocation and budget. Producers must be completed children from strictly earlier frozen steps in the same scope. An observation must be linked by the producer's durable `result.routed_decision` or `result.routed_stage_decision` to the corresponding hashed controller finalization artifact. The finalizer artifact and its publication/decision events must agree. Arbitrary worker JSON or a file with a persuasive provenance string is insufficient.

Supported data are finalized `worker_observation` summaries, scoped `controller_task_acceptance_decision` projections, and authenticated `controller_stage_contract` projections. Task-finalized observations project only the final successful adapter summary plus producer role/input/provenance; stage-finalized observations preserve the normalized structured output described below. Tool traces and private storage paths are not included. Raw files are limited to 256 KiB each and 1 MiB in aggregate; final text is limited to 64 KiB. Oversize inputs fail explicitly rather than silently truncate. Reads require regular, single-link, controller-owned, non-writable-by-group/others files with no symlink traversal, stable descriptor metadata and exact registered bytes/hash. Known-secret policy is validated before any early return; raw bytes, decoded JSON fields and projected nested summary JSON are scanned with fixed errors. Authority and all referenced database rows are rechecked after reads.

No scheduler, runtime, adapter or database schema changes were made by this module. Successful authority observations use the existing bounded scheduler control transaction and durable budget high-water logic; no inference requests are charged.

The stage-contract branch calls `routed_stage_decision.load_finalized_stage` inside both bounded authority snapshots. This authenticates the canonical controller decision, producer pointer, launch, referenced metadata and lifecycle/events. Both direct stage-artifact references and linked observation references project the complete normalized `StageOutput` (plan, findings, evidence and recommendation/status), labeled `worker_reported` with `verification_scope='stage_contract'`. For observation references the parsed saved summary must equal the finalized structured output. The projection validator reparses the exact stage schema; unknown fields or authority upgrades are rejected. Task-acceptance artifacts retain their original branch.

The production progression policy, not this loader, chooses the exact ordered all-prior artifact references and immediate predecessor's carried revision. The loader enforces only that supplied references are unique finalized earlier stages in the same scope. Five maximum-size stage outputs may exceed the 64 KiB context limit: refusal is explicit and the loader never discards findings or silently summarizes a plan. Missing finalization, ambiguous task/stage pointers or failed finalizer authentication are refused. This does not itself admit a next stage, authorize a gate, promote a revision or claim live six-stage execution.

## Adapter-side projection validation

`validate_stage_context(context, *, input_revision_sha256, context_refs) -> StageContext` returns the original object after validation. Expected references are an ordered tuple/list of exact artifact ID/hash dictionaries. The helper validates exact inner schemas, strict integer generations, ID/hash shapes, input and assignment hash consistency, reference order, canonical encoding, recomputed digest, deterministic wrapper text and the 64 KiB projection bound. Rehashed unknown fields or scope changes are refused; invalid Unicode produces a fixed error. The loader itself uses this helper before returning. This is an integrity check of the supplied projection, not an independent database authorization or a way to authenticate a fully forged object from an untrusted caller.


## Stage-context test boundaries

The context unit tests exercise real Store/scheduler scope and protected file reads with a clearly labeled synthetic finalization seam for stage projections. These prove full plan/review preservation, observation linkage, before/after finalizer consistency, secret rejection, bounds and rehashed schema tamper refusal. They do not substitute for the durable finalizer's own execution/authentication tests or live provider evidence.


The final 54-test run additionally uses the real saved-observation/candidate pipeline, `complete_stage`, historical authenticated loader and typed release to finalize planning, admit the next frozen stage and load both its stage artifact and linked observation. The complete plan and validation step are preserved. It uses synthetic Docker/provider adapters and does not claim live provider execution. The initial integration run exposed the separately corrected shared PinnedCLI path-serialization issue before context loading. A subsequent fixture correctly encountered `parent_identity_already_bound` when it tried to change the root native session; the fixture was corrected to preserve its original native identity, without relaxing broker authority.

UTF-8 regression: stage-output reparsing explicitly uses compact `ensure_ascii=False`, matching the finalizer. Valid near-limit CJK and emoji reports remain accepted; the complete projected context still independently obeys64KiB. Current Store.encode already used UTF-8, so the initial ASCII-expansion suspicion was not a confirmed source defect. The first regression fixture incorrectly assumed ASCII Store encoding and exceeded summary bytes; corrected fixtures respect the8192-byte summary bound. Final focused suite:56 passed.
