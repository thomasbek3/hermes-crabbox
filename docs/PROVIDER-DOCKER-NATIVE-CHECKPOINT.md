# Native provider Docker checkpoint

Local implementation only. No image build, deployment, real provider call, credential read, account registration or live schema change occurred. Fable review is pending: parent reported the reviewer account session limit and instructed this unit not to start another review while that limit remains unchanged. Earlier Claude-only review/live receipts do not qualify this new branch.

`DockerConfig` remains the immutable controller-supplied launch contract. The profile's raw SHA256 and canonical profile digest must both match. A native profile has exactly four string fields: `transport: native-responses-v1`, `provider`, `model`, and `effort`. `NativeProfile` validates the supported exact provider/model/effort route and computes the digest including its endpoint. Duplicate JSON keys, extra/missing keys, invalid field types and unsupported routes fail before Docker. The historical five-field `PinnedCLI` contract and digest remain supported.

Native credentials mount readonly at `/run/secrets/native-auth.json`; historical Claude credentials still mount readonly at `/run/secrets/claude-token`. Only native credential metadata accepts up to 64KiB; historical credentials retain the 4096-byte bound. Both require a regular single-link provider-readable file with no group write or world access, and trusted parent directories. The controller never reads credential bytes. No secret enters argv or the gateway. Provider identity remains UID958:GID959; existing login files owned by another principal require an explicitly qualified operator staging step before use. This implementation does not perform that step.

Create and inspect derive the exact expected credential destination from the validated profile. Inspection rejects writable, extra, omitted, duplicate or swapped destinations and wrong source paths. A reconstructed adapter validates the same profile before reusing its durable journal. Start revalidates the raw profile hash and credential metadata before starting either container. Inspection and exact labeled cleanup remain available on an existing adapter if a profile is subsequently damaged; damaged configuration must not prevent cleanup of known objects. Trusted root-owned files must remain immutable during launch; this unit does not claim protection against concurrent privileged host mutation.

The same `/opt/hermes/venv/bin/python` wrapper invokes `cloudworkbench.provider_main --profile /run/provider/profile.json --proxy <private gateway>`. No native CLI or parallel runtime stack is added. The profile and credential are mounted only into the provider container. The caller still supplies a separately trusted domain allowlist; this unit does not derive account routing or authorize domains from model arguments.

Evidence: `evidence/provider-docker-native-tests.xml` and `.log`, with exact source/test hashes in `evidence/provider-docker-native-binding.json` and snapshot `evidence/provider-docker-native-source/`. Tests use fake Docker with real Store/leases/dispatcher admission and synthetic credential metadata; no credential content is read. Covered: all three current native profiles, complete dispatch/collect/cleanup, profile mismatch and invalid profiles, native credential limits, mount tampering, pre-start profile drift, cleanup after drift, reconstruction and historical adapter regressions.

Remaining activation gates: bounded Fable review/disposition; source-bound image containing matching provider_main/native modules; real isolated Docker proof of native mounts, permission handoff and deny paths; approved dedicated credential staging; actual native provider protocol and cleanup qualification under mandatory budget, cancellation and lease supervision. None is replaced by the fake Docker tests.
