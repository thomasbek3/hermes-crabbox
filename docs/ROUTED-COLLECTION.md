# Routed caller observations and output collection

`collect_execution(read_file, *, launch_receipt_sha256, limits=CollectionLimits(), clock=None)` reads a terminal worker observation while the caller init container remains running. The trusted driver supplies a closure over the exact admitted spec and full runtime ID, calling `RoutedRuntime.read_caller_file` with the collector's fixed `name`, `offset` and `max_bytes` arguments. The closure must check current attempt, generation, owner, cancellation and reservation authority before each RPC. Collection itself performs no Store transition or runtime mutation.

The frozen `ExecutionObservation` retains exact bounded UTF-8 `result_json` and `events_jsonl` records for later controller publication, in addition to status, failure, exit code, stderr byte count, exact expected launch receipt hash, immutable event tuples, and result/event inode, size, mtime and SHA256 evidence. Each `WorkerEvent` has type, a fresh decoded payload property, and byte offsets. All evidence is `worker_reported`; `verification_pass` is always false and `outer_cleanup_required` always true. A tool running as the caller UID can forge these files. File identity and hashes detect observed changes; they do not authenticate a truthful execution or defeat a malicious writer that coordinates its changes between reads.

Initial missing files raise `CollectionNotReady` with a fixed code. Malformed, truncated, oversized, changed or conflicting records raise `CollectionError` with a fixed code. An absent second snapshot is a changed-file error. Result fields are exact and must bind the trusted launch receipt. Events must match the existing public spool schema exactly, including JSON boolean types; reserved controller events, unknown fields, coercions, duplicate JSON keys and nonfinite values are refused. Completed observations require zero exit status, no failure, exactly one final non-error adapter result, no permission denials, and no error event. A failed worker receipt can describe a failure without an adapter result, provided its event file contains complete valid records. An empty or incomplete event file is refused even for a failed receipt; the controller must still clean up the failed caller separately.

Reads check offsets, byte counts, inode, size and mtime across chunks. After result publication, both files are read twice and must agree byte-for-byte as well as on metadata. Defaults permit at most 16 MiB of event data and 10,000 events, with a 64 KiB event-record cap, 1 MiB event-read chunks, 64 KiB result cap and a 30-second cooperative deadline. Relay readiness/fence records are capped at 4 KiB. Snapshot rereading transfers at most twice the allowed file bytes. The injected clock is shared with the driver when supplied. Deadline expiry remains a failure, never a blind `CollectionNotReady` retry. The reader's Docker operation currently has its own five-second timeout. The collector cannot interrupt a blocked reader or kernel operation, and parsing work is bounded by bytes/records rather than a hard wall timer. The runtime caps decoded event chunks at 1 MiB and base64 envelopes at `4*ceil(max_bytes/3)+4096`, traverses each fixed path component without following symlinks, and checks file metadata again after reading. Run collection outside the scheduling/cancellation tick; check cancellation between RPCs and retain a separate bounded caller cleanup path.

Worker result/events now use `/scratch/.cwb-observations/{result.json,events.jsonl}` on the existing durable attempt scratch bind. Removing the caller must not remove that host scratch or its volume. The relay readiness/fence records remain private `/run/relay` state. Retention/reconciliation must preserve the exact bound attempt scratch when collection fails or times out; the reader never deletes it and cannot read via Docker exec after removal. A later controller reconciliation needs an identity-bound reader for the retained files, not a fresh inference or an assumption of success.

The order is: collect terminal records while init is running; retain the observation as untrusted execution evidence; stop and confirm physical caller cleanup; only then schedule protected verification or authorize revision capture. A worker's `completed` field is not a verification pass, successful workflow gate, delivered revision, or physical stop receipt. Missing/invalid evidence must never skip physical cleanup.

## Stopped workspace export

`routed_export.py` now implements the separate UID1000 collector described by this boundary; `routed_export_protocol.py` implements descriptor-safe selected reads and independent strict decoding. The original PreparedStage workspace device/inode is required. The collector receives only the exact workspace read-only, with network none, dropped capabilities, a read-only root and declared CPU/memory/PID limits. It receives no credentials, worker socket, task directory, scratch or personal HOME. See ROUTED-EXPORT.md and ROUTED-EXPORT-PROTOCOL.md.

Export bytes are spooled to a bounded private controller file before collector removal. Complete collection evidence and exact cleanup permit `load_workspace_export` to reconstruct the same bytes without another create/start. Partial streams and unknown effects are not successful candidates. Restore still requires valid current controller authority; it does not adopt another controller's account reservations.

`routed_candidate.py` revalidates the export and combined cleanup, captures an immutable WorkspaceRevision and registers its manifest under current authority. It leaves the workflow gate, child state, scheduler seat and delivered session revision unchanged. `routed_publication.py` separately publishes revalidated worker observations with explicit worker-reported provenance. See ROUTED-CANDIDATE.md and ROUTED-PUBLICATION.md. Production orchestration, protected verifier outcomes and delivered revision promotion remain open.

## Evidence

`tests/test_routed_collection.py` covers real local supervisor records, strict schemas, malformed JSON, missing files, byte/offset limits, multi-chunk reads, same-size byte changes, inode/mtime drift, disappearing second snapshots, conflicting terminal evidence, reserved event refusal and cancellation/deadline propagation. Corrective coverage exercises an 8 MiB event spool with an injected 100 ms-per-read clock (20 reads including both snapshots), and executes the actual runtime reader program locally through the runtime base64 decoder for a 1 MiB chunk and tail. The simulated timing shows scaling only; it is not a target-host Docker throughput measurement. Strict envelope/encoded caps, parent-symlink refusal and per-path file limits are also tested. These are local synthetic tests, with no provider calls, live services, host provisioning or Docker qualification.
