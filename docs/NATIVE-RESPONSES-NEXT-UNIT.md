# Next bounded implementation unit: native Responses adapter

Goal: prove the exact Astra/high, Sol/max and Grok4.6/xhigh inference/tool roundtrip through a disposable provider process while Hermes remains the tool executor. This is a provider boundary addition, not another scheduler, credential discovery system or direct Codex/Grok agent delegation.

Own one new `responses_transport.py` with focused tests and a thin provider entrypoint only after its protocol tests pass. Reuse the controller's existing relay, budget, account reservation, cancellation, Docker lifecycle and cleanup requirements. Keep the current Claude CLI provider intact and explicit.

The frozen native profile must identify provider (`openai-codex` or approved xAI route), exact endpoint policy, native model, exact effort and approved credential reference. A model/effort pair outside the fixed policy refuses. Token loading belongs inside the isolated provider process; the host controller and Hermes/tool process receive no credential bytes. No copying personal CLI auth into a cloud capsule, no ambient fallback or implicit API spending.

Implement bounded conversion of the existing native Hermes request into Responses input: user/assistant content, function calls and correlated function_call_output. Preserve call IDs, JSON arguments and the required read/write/patch/search/terminal tool schemas. Support the terminal response shapes needed for text or tool calls; preserve unknown usage and worker-reported identity rather than claiming provider attestation. Reject unsupported/malformed frames and mismatched reported models. A supplied transport interface allows deterministic fixture testing first; network activation remains gated.

Acceptance fixtures should exercise each exact policy pair through two turns: provider emits read_file, actual or fixture Hermes tool result returns with the same call ID, provider emits a final result that uses it. Include fragmented frames, output caps, deadline/cancellation, malformed arguments, duplicate IDs, model mismatch, unsupported effort,401/429, missing usage and interrupted stream. No hidden retry or lower-effort substitution. Subsequent isolated Docker qualification binds the actual native Hermes→relay→controller→provider path with fake HTTP responses before any approved real account is mounted.

Dedicated account setup remains separate: inspected cloud config/auth paths have no Codex or Grok reference; parent title-only vault inventory found no approved Grok/xAI key. Existing personal CLI logins are not cloud authorization. OAuth refresh ownership and provider egress must be qualified for the chosen route before real execution. Source support in Hermes is available; these account and isolation interfaces are the missing work, not a need to replace Hermes with another agent CLI.
