# Protected routed verification policy and receipt protocol

`routed_verification_policy.py` is pure controller-side policy. It does not execute checks, read/write files, modify scheduler state, or independently prove that a record came from Docker. Model text and stdout are not verification records. The lifecycle/composition layer must independently bind and inspect actual runtime identity, protected file provenance, immutable candidate mounts, execution status and confirmed physical cleanup.

Build with `build_verification_plan(binding=RevisionBinding(...), input_revision_sha256=..., candidate_revision_sha256=..., launch_binding_sha256=..., cleanup_sha256=..., environment=manifest_dict, scripts={script_id: bytes}, acceptance=[{id,description,mandatory}], limits=VerificationLimits())`. Environment validation and canonical hash come from `environments.validate_manifest`; project must match the binding. Every check requires a protected script ID/name/SHA256 and its exact `/run/task/<name>` argument. The runtime layer additionally constrains executable/interpreter shape; presence of that argument alone is not executable-policy qualification.

Plans are frozen dataclasses. Checks have immutable tuple argv and immutable script bytes, with bytes excluded from repr and `to_dict()`/canonical serialization. Use `plan.to_dict()` or `plan.canonical_json`, not generic `dataclasses.asdict(plan)`, for public serialization. The latter would include script bytes. The canonical JSON is a string; `.digest` hashes its UTF-8 bytes. The plan includes schema version1, complete root/child RevisionBinding, distinct input/candidate revisions, launch and cleanup hashes, normalized environment hash, immutable image digest, checks, acceptance and limits. Image field is `plan.image`.

At most32 checks are permitted; each script is nonempty and at most1MiB, with4MiB aggregate. Script map must exactly cover referenced IDs. Colliding script filenames with different hashes are rejected. Acceptance is at most100 exact `{id, description, mandatory}` records using the existing AcceptanceCriterion constraints, with real booleans and no coercion. Check IDs and acceptance IDs are unique. Limits are `max_seconds` (default600,1–600), `cpus` (default1, integer1–2), `memory_mib` (default512,128–4096), `pids` (default128,16–512), and `max_log_bytes` (default65536,0–1048576). Total plan serialization is bounded at512KiB.

`CheckExecution(check_id, runtime_id, exit_code, oom, timed_out, cleanup_confirmed, logs_sha256)` describes a controller-observed single-check container. Runtime IDs and diagnostic-log hashes are64 lowercase hex characters. Exit codes are integers0–255; flag fields are strict booleans. `assess_verification(plan, records)` accepts a list/tuple of these exact objects or exact-shape dictionaries. It requires the full ordered check set without duplicate runtime IDs. Missing/invalid records, OOM and unconfirmed cleanup raise fixed `VerificationError` codes; no receipt can pass through those conditions.

Assessment returns a frozen `VerificationReceipt` with plan hash, immutable records, outcome, remaining mandatory criterion IDs and schema version1. Nonzero exit or timeout yields `rejected`; otherwise no checks or missing mandatory coverage yields `needs_review`. `passed` requires a nonempty exact check set, all successful exits and cleanup, and each mandatory acceptance ID plus description matching its passed protected definition. Optional unmatched criteria do not block a pass. This is protected-check coverage, not a model-review decision or workflow gate.

`validate_receipt(plan, receipt)` recomputes the entire policy result and compares canonical bytes. `require_exact_replay(plan, previous, current)` validates both and requires exact equality including runtime/log hashes. These functions detect changed policy/results; they do not authenticate who supplied a receipt. Parent composition remains responsible for strict disk loading, secret scanning, runtime/file provenance, cleanup journals and current authority. Constructing a dataclass never creates such authority.
