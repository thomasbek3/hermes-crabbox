# Local preview gateway foundation

This checkpoint adds `preview_gateway.py`, a standalone ASGI HTTP application and a WebSocket lifecycle guard around the private registry. It is provider-neutral: Hermes or another trusted worker integration supplies the same registered backend metadata. No API mount, Store integration, server entrypoint, listener, DNS/TLS, Docker network, environment manifest, dashboard link or deployment is added. Existing running services are unchanged.

## Trust and integration

`PreviewGateway()` denies503 until supplied a `PreviewRegistry` and mandatory asynchronous `backend_validator(AuthorizedPreview) -> bool`. Only literalTrue authorizes dialing. The validator must prove exact worker/container/network ownership, session/attempt/generation and current network address/service readiness against trusted worker state. The registry's authority callback independently checks current owner/project/client revision and active generation. Neither callback may derive its answer from request fields or merely trust registration presence.

The request must have one canonical Host in the registry's configured HTTPS origins and a trusted ASGI `scheme=https`. A deployment must terminate TLS for that exact host and prevent forged forwarded headers from changing the scheme; this module does not configure that listener. It ignores and strips inbound Forwarded/X-Forwarded headers. It dials only the validated numeric `WorkerBackend.address/port` through `BackendTransport`; no request-selected URL, backend hostname, port, Docker ID or DNS lookup is accepted. HTTPS backends use standard certificate verification against the numeric IP; no insecure TLS mode is provided. The injectable transport is a trusted implementation/test seam, never client input.

Platform Authorization, Proxy-Authorization, API-key/auth-token/CSRF headers, Referer, platform cookies and hop headers are stripped before any upstream write. App cookies remain per-preview-host. Upstream platform Set-Cookie or any Domain cookie is rejected; hop/auth headers, Refresh, Alt-Svc and Clear-Site-Data are removed. Exact-origin or root-relative HTTP Location redirects are allowed; cross-origin, protocol-relative, credentialed and backslash forms are denied. The gateway never follows redirects. This does not rewrite arbitrary app HTML/JavaScript or prevent its own navigation; untrusted previews require genuinely distinct browser origins.

Request header/cookie control characters, duplicate sensitive headers/cookie names, absolute-form targets, request Transfer-Encoding and Expect are denied. The ASGI server is responsible for parsing/dechunking the incoming HTTP wire safely before calling the app. Upstream parsing supports a strict HTTP/1.0/1.1 subset: bounded headers, one Content-Length, chunked bodies without extensions/trailers, or EOF framing. Informational/101 responses, duplicate lengths, conflicting framing and malformed chunks fail closed. The front end must use the qualified HTTP/1.1 form: HTTP/2 split Cookie headers are unsupported unless a separately qualified front end normalizes them. Quoted cookie values, duplicate Cookie headers and trailing cookie semicolons are rejected. Expect:100-continue is unsupported. Location policy applies to every response status, including201; a cross-origin Location metadata field is deliberately denied. No HTTP/2, CONNECT, proxy authentication, pooling, compression decoding, automatic retry or redirect following is implemented. Response byte limits count transferred bytes, not a compressed body's decoded browser size.

## Streaming and revocation

Defaults:16 active HTTP/WS leases,32KiB/100 headers,8MiB request body,32MiB response body,64KiB chunks,15-second idle deadline,120-second connection lifetime, and2-second authority/backend rechecks. Every HTTP request reauthorizes; connection setup revalidates before upstream headers. Read, drain and ASGI send await completion before the next chunk, retaining backpressure. After the final request-body event is received, the disconnect watcher runs before backend dialing; an observed disconnect cancels pending I/O and closes the upstream. Tests prove cancellation during dialing for an empty completed request and during a stalled response. For an unfinished upload, the next ASGI receive detects disconnect, but a disconnect while backend dialing is pending may wait for the idle deadline. Immediate disconnect observation during that specific phase remains unproven. Timeout, failed recheck, generation/backend identity change, malformed framing or size exhaustion closes the connection. If response headers were already delivered, the ASGI call raises `ConnectionError('preview_stream_closed')` so the hosting server must abort the incomplete response; it does not fabricate a successful replacement body. This hosting-server behavior still needs actual server/browser qualification.

Registry operations use at most4 dedicated worker threads and4 submitted slots. Active requests wait for a slot for at most one recheck interval; ordinary contention queues, while exhausted/deadline-expired authority returns503 rather than falsely claiming revocation. Authenticated connections retain their separate16-connection cap. Unauthenticated grant exchanges use a separate2-request bucket and at most2 seconds to receive a body, so stalled exchanges cannot occupy authenticated connection capacity. A timeout keeps its slot reserved until the actual call finishes, preventing unlimited queued background calls. Backend validation is asynchronous with a recheck-duration timeout. A stuck trusted synchronous registry resolver cannot be forcibly stopped by Python; it consumes one bounded slot and further operations eventually deny. Production integration must use a bounded resolver and worker-state reads. Call `gateway.close()` at application shutdown; it rejects further executor submissions and cancels queued work, but cannot kill already-running Python callbacks.

## Cookie exchange and WebSocket boundary

Empty final request bodies use Content-Length:0 upstream, rather than a chunked empty GET. POST `/__cwb/exchange` accepts only a1024-byte bounded URL-encoded grant body, exact dashboard Origin and content type, with no query string. It returns a200 minimal CSP-restricted/no-store/no-referrer document and the Secure/HttpOnly/host-only Strict cookie. The document offers an **Open preview** link to `/`, making the next navigation originate from the preview document. No grant appears in the URL, landing body, upstream request or response redirect. This intentionally avoids assuming that a cross-site-initiated302 sends a Strict cookie. Actual browser acceptance, cookie persistence and login/revoke flows remain unproven; ASGI tests do not establish them.

`websocket_lease(cookie, origin, request_origin)` returns a lifecycle interface for a future qualified framed transport. `start(async_close_callback)` authenticates and reserves capacity. `permit_frame(bytes)` authorizes every incoming or outgoing application frame, bounds individual/cumulative bytes and frame count, and refuses frames after closure. A watchdog periodically rechecks authority/backend identity, idle time and lifetime, then calls the close callback with1008 on loss of authority. Closure immediately blocks further frames; a close callback error/timeout retains the capacity reservation until an explicit successful close retry. A future relay must invoke this before forwarding **both directions**, bound its own decoded frames/control messages/buffers, and enforce close delivery. The current ASGI WebSocket route always closes1008: no RFC6455 handshake or wire relay capability is claimed.

## Evidence and next work

Tests use disposable TCP servers bound only to local127.0.0.1 random ports. A test-only transport maps an otherwise valid private backend identity to that fixture. Production `BackendTransport` remains numeric-private-target only; the tests do not prove real Docker network isolation or ownership. Tests simulate trusted HTTPS ASGI scopes and do not create TLS certificates or DNS records.

Covered: secret stripping observed in actual upstream fixture bytes; exact Host/Origin/cookie validation; backend-validator denial before dial; streaming framing and size limits; timeout/backpressure; revocation during stalled responses; exchange replay denial and landing headers; per-frame/periodic WS revocation and shared capacity. Gateway and registry tests are bound in the checkpoint receipt.

Remaining B02/B03 gates: real Store authority and trusted worker backend attestation; service/network admission and resource accounting; actual TLS/private origins and a clean preview origin/service-worker policy preventing grant-exchange interception; ASGI server/browser streaming/disconnect and Strict-cookie navigation; real wire WebSocket relay; cross-session Docker/browser isolation; restart/cancel/retention integration; target-host load; owner opening a delivered preview. No Release B completion or live preview claim follows from this foundation. Sequencing now returns to the minimal real Hermes+pstack two-model coding/review workflow before further gateway expansion.
