# Supervised failed-call recovery

The wrapper closes and joins its cancellation observer before considering recovery. A stopped observer does not itself prove runtime cleanup. Missing or stuck observer shutdown fences this wrapper and quarantines the reservation; it never invokes recovery.

A non-success response with unconfirmed cleanup may locate only its exact durable dispatch row: reservation, grant, attempt, generation, profile, request nonce and normalized provider-transcript hash must match. Before lookup the original native payload hash must match DispatchContext. Normalization uses the same admitted protocol as ProviderExecutor but does not admit a new request, charge budget, create resources or repeat inference. The row must already be quarantined, cleaned or delivered. The same-instance provider_recovery helper then takes the account lock and rechecks immutable identity and current state. Running rows are never recovery candidates. Unknown daemon effects remain quarantined when the trusted runtime cannot settle them.

Successful recovery changes only DispatchResult.outer_cleanup_confirmed; the original failure status/body remains unchanged. last_recovery_receipt is internal evidence of the matched helper result. It does not release the account owner, unquarantine an authentication failure, restore revoked grants or authorize a retry. The wrapper retains its per-instance execution lock through cleanup, so a concurrent call cannot replace the supervisor or interfere with this request's recovery.

This is same-controller failed-call cleanup, not process-crash owner adoption. The actual Docker adapter can resolve only acknowledged operations or trusted definitive no-effect outcomes. An unanswered daemon RPC remains held. No deployment, provider credential, paid inference or automatic account release is part of this delta.

Recovery refusals/failures have a bounded `last_recovery_error` code. Known settlement/binding errors retain their allowlisted code; unexpected database/runtime errors become `recovery_failed`. No raw exception text is retained. This complements the success-only helper receipt. The wrapper fence is per instance; reservation quarantine is best-effort when the database itself fails. A new wrapper is not a recovery or ownership transfer mechanism.

The reviewed uncertainty guard lives in ProviderDispatch: reconcile returns only after its durable CAS clears uncertainty; cleanup independently refuses uncertain state before physical cleanup. A regression that makes reconcile return without settlement still cannot reach the verifier. The schema's unique `(attempt_id, generation, request_nonce)` key makes the more restrictive recovery lookup singular. `delivered` is reachable only from physically cleaned state. Native payload normalization is the existing deterministic protocol conversion used during initial admission; it does not make a provider call.
