# Hermes adapter source foundation

Local, unqualified source foundation only. It is not wired into entrypoint, Runner, Store, API or a deployed image. Existing direct-Claude execution identities remain unchanged.

SPEC-FIRST-CONTRACT D1 supersedes the earlier native-auth integration proposal: routed Hermes must have no provider credentials in its environment or filesystem. A separate provider service owns credentials and refresh. `build_launch` remains a source-only probe for audited native Hermes CLI/config syntax. Its receipt states `execution_authorized=false`, `live_qualified=false` and `routed_execution_requires=provider_service_only_transport`. Do not use this plan to inject credentials or activate a workflow. A future service transport needs its own reviewed launch/config contract and actual qualification.

`build_launch(BackendProfile, toolsets=('terminal','file'), max_turns=32, run_budget_seconds=300)` returns immutable argv/env/config and a controller plan receipt. The supported native combinations are anthropic/anthropic_messages and openai-codex/xai/xai-oauth with codex_responses. Slash/colon model prefixes, arbitrary providers/endpoints, unsupported toolsets and budgets are refused. Qualification hashes are references, never trusted qualification decisions. `live_qualified` cannot be set through the constructor or dataclass replacement.

The environment is a fresh allowlist with isolated HOME/HERMES_HOME, Codex/Claude and XDG paths. Plugin discovery is disabled through env HERMES_SAFE_MODE. The CLI `--safe-mode` flag is omitted because it would also discard generated config. `--ignore-rules` suppresses ambient context and automatic skill preload; explicitly requested `--skills` can still load in the pinned source. The current plan requests no skills and does not expose delegation. MCP/hooks/fallback lists are empty, auxiliary configurations are pinned, background review/title generation are disabled and approval mode is deny. Terminal commands have a separate timeout capped at180 seconds; the process budget may be longer.

`check_clean_layout(..., isolation_root, plan)` requires exactly config.yaml in the profile, verifies its full bytes against the plan using a bounded nofollow regular-file read, rejects hardlinked config and unexpected profile state, and checks isolated directories are empty. Dotenv/project-plugin paths and symlinked roots are refused. This read-only check requires protected immutable mounts and cannot defeat a concurrent writer. It is a fresh-start source probe: it rejects native auth/session state and does not claim native resume. The controller must independently prove source/image hashes, mount boundaries and runtime enforcement. Never run the fixed container argv on the controller host.

`JsonlParser` accepts chunks/lines at most64KiB, total16MiB and8192 events, with output text chunks at most16KiB in UTF-8 bytes. It requires one init and one terminal result; malformed Unicode/JSON, nonfinite numbers, ordering errors, missing results and oversized input fail with fixed codes and close the parser. Every instance owns its buffers. Independent process status and protected verification are still required.

Public output contains worker-reported init model/session IDs, assistant text, tool names/IDs and a result. Tool arguments/output and raw error strings are omitted. Known UTF-8 secrets are redacted after JSON decoding and across text deltas. Text can be held back up to4095 characters and emitted after an intervening tool event; public event order therefore reflects safe publication order, not exact native chronological order. Flushing that held suffix would leak a split secret. One-byte secret values are deliberately supported and may over-redact; this is preferable to exposing a caller-declared secret. This is exact-known-value screening, not unknown-secret detection. Stderr/files need independent bounded screening.

The pinned emitter substitutes zero for absent token counts: all-zero usage stays unknown; positive values are worker-reported with unknown defaults. Cost and HTTP/auth status remain unknown. Nonzero exit or a nonempty error field means generic execution failure, without publishing raw errors or inferring401/quarantine from prose. Unexpected event types fail closed. Tests use the repository's hash-pinned emitter snapshot, including failed/error-only/explicit-exit paths and ignored nonprotocol callbacks; no personal install or skip is needed for these tests.

The separate offline discovery harness imports the clean pinned git archive with temporary homes, network denial and an audit guard against external auth/config/dotenv reads. It verifies pstack-only enablement,50 registered namespaced skills, explicit poteto preload, builtin provider module source and denial of an unapproved entrypoint. It also verifies the real config loader plus approval and memory consumers. Hermes preserves unknown keys rather than rejecting them, so loading/hashing config is not sufficient proof of every setting or effective model route. See HERMES-CONFIG-AUDIT.md for source pointers and limits.

This discovery proof does not implement D5's patched role tools/workflow allowlist. No trusted pstack launch variant has been enabled: upstream skills still need transitive delegation adaptation, tool-schema tests, broker capability binding and immutable patch digests. Other gates remain the provider-service transport, effective route/effort evidence, qualified image, durable parent/child scheduling/cancellation/recovery, native continuation and real authorized two-model execution. The shared spool also needs explicit tool.completed support. No provider calls or new credentials were used here.
