# Private preview registry foundation

This implements the grant/registry portion of Release B B00/B02. It does not expose a preview, configure DNS/TLS, attach networks, proxy traffic, authorize a browser session, or prove Docker ownership. B01/B03 and live browser/isolation acceptance remain open. Unconfigured origins, service policy or authority callback deny access.

## Integration contract

Create `PreviewRegistry` with a dedicated controller-owned absolute database path (600, immediate parent owned by the controller with permissions 0700 or inherited-setgid 2700), exact dashboard HTTPS origin, explicitly provisioned preview HTTPS origins, service-name to `(protocol, port)` policy, and a fresh authority resolver. This database is independent of the existing Store; no production migration is included.

The resolver has one signature: `authority(PreviewBinding, PreviewPrincipal) -> bool`. Only literal `True` grants access; errors deny. On each call it must verify the client is active, its credential revision still matches, required scope/project access remains valid, the session belongs to that owner and project, the attempt/generation is current, and the registered service remains ready. The module independently checks principal owner equality. The module cannot derive current Store or runtime state. Do not implement the resolver as unconditional success in integration.

`register_worker_backend` is a trusted worker/control-plane interface, never an HTTP request body passthrough. The worker must prove exact owned container/network IDs and generation, discover the numeric backend address, and perform service readiness checks before setting `readiness_proven=True`. `WorkerBackend` validates representation and private numeric address/service policy; it cannot prove the address is actually inside the owned isolated network. The future gateway must independently enforce that binding before connecting. No arbitrary URL is accepted by grant/exchange/lookup methods.

Every registration is immutable and short-lived (default 900 seconds, maximum 3600). Replacement at the same origin revokes previous registration grants and cookies. Each hostname is permanently reserved to one owner/project/session within this database, including after revocation or expiry. Different ports are not a cookie isolation boundary; explicit ports are rejected. Origins must be canonical lowercase HTTPS DNS hostnames without path, credentials, wildcard, query or fragment. Configuration is an operator assertion, not evidence that DNS or TLS exists.

The dashboard authenticates its session and same-origin CSRF mutation before calling `issue_grant`. Principal identity and revision must come from that authentication, never request fields. Grants expire in 30 seconds by default (maximum 60), and are bound to registration, exact origin and principal. Transport the grant using a top-level form POST navigation to the exact preview origin, never query strings, local storage, logs or a cross-site fetch. The exchange response must be a minimal 200 document on the preview origin that sets the cookie and then performs a fresh same-origin navigation; do not rely on a cross-site-initiated 302 carrying a Strict cookie. The future gateway must use no-store, no-referrer and a restrictive CSP on that exchange document. This browser flow is a design constraint awaiting real browser proof in B03. `exchange` requires POST with the exact dashboard Origin and consumes the grant atomically when creating the cookie; simultaneous requests produce one winner. A lost successful response requires a new dashboard grant, not replay.

The browser receives `IssuedCookie.cookie_options()`: `__Host-cloud_workbench_preview`, `Secure`, `HttpOnly`, `Path=/`, `SameSite=Strict`, no Domain. Cookie lifetime is at most 900 seconds and cannot exceed registration expiry. Set it only on the returned exact HTTPS origin. These constraints follow the [MDN Set-Cookie documentation](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie). Only grant/cookie hashes are stored; returned token objects hide tokens from repr. Their raw fields and cookie options are still secrets and must not be logged or serialized into evidence.

The gateway resolves the actual request Host against trusted configured origins, calls `lookup_cookie`, and routes only to its returned immutable backend identity. Never derive `preview_origin` from untrusted forwarded headers. Every HTTP request rechecks authority. WebSocket handshakes require `websocket=True`; mutations and WebSockets require exact preview Origin. Safe navigations may omit Origin, but an explicit foreign Origin is denied. The gateway must strip platform Authorization, preview/session cookies and exchange grants before sending any request upstream. `AuthorizedPreview` contains no credentials. This module alone does not implement or prove header stripping, request/body limits, TLS, WebSocket connection lifetime limits or active connection closure on revocation.

Call `revoke_registration` with the exact expected binding or the trusted `revoke_session` lifecycle hook on cancellation, stop, retention deletion and generation changes. Cookie revocation and persisted registry state survive process restart. The authority resolver must independently deny stale state even if a lifecycle hook was missed. Existing accepted connections need separate gateway termination/revalidation; cookie lookup only authorizes a request or handshake.

## Bounds and failure behavior

The dedicated DB serializes modifications with SQLite `BEGIN IMMEDIATE` and a 3-second lock timeout. Authority callbacks execute outside the database transaction; the registration/capability is checked again afterward. Successful lookups still persist the clock fence in a short write transaction. Local concurrency proof does not establish production throughput on the target disk. It has at most 1024 active registrations, 4096 outstanding grants and 4096 cookies, with per-owner limits of 64 grants and 128 cookies. Expired/revoked registrations and expired/used capabilities are pruned on issuance/replacement. Origin assignments are retained to prevent cookie-host reuse. Capacity exhaustion denies new capabilities. A finite operator-provisioned origin pool cannot serve more sessions than its unique hosts; an operator can provision and configure fresh exact hosts while retaining this database, but cannot reassign old hosts across sessions. No automatic DNS provisioning, reservation deletion, unbounded hostname pool or background sweeper is implemented. Integration also needs authenticated endpoint rate limits. No raw tokens are persisted, including SQLite journal records.

A persistent observed wall-clock high-water mark prevents expired capabilities reviving after rollback, including when the request observing expiry was rejected. A read snapshot precedes each authority callback; no transaction is held while the resolver runs. External Store state is not made atomically transactional with this standalone database, so the gateway must retain its own connection lifetime and revocation safeguards. Clock regression or invalid time denies capability operations until time catches up. The trusted operator-only `reset_clock(operator_confirmed=True)` repair invalidates all registrations, grants and cookies before resetting the fence to the corrected clock; permanent hostname reservations survive. This repair is not an HTTP endpoint and must not be exposed to a preview job or client. A clock repair never preserves previously issued authority. Registry file corruption, unavailability and schema mismatch fail closed; no fallback to unprotected proxying is permitted. Trusted parent ownership is assumed throughout process lifetime; do not expose the DB directory to jobs.

Focused tests cover races across independent SQLite connections, restart persistence, current owner/project/session/attempt/generation and credential-revision changes, exact origin checks, host-only cookie options, expiry rollback, revocation, immutable backend policy and secret-free persisted bytes. These are local module tests, not deployed browser, DNS, network or container proof.
