# Cloud role socket and native handlers

This checkpoint connects the isolated cloud plugin's actual D8-patched native handlers through bounded HTTP over a per-attempt Unix socket to durable RoleBroker records. It is local source/fixture proof. No provider call, cloud image build, personal Hermes modification, Store/Runner/API wiring or deployment occurred. No real child scheduler runs. `cloud_get_role_results` currently returns a pending/blocked/rejected/linked receipt only; it must not be presented as completed child results.

## Trusted setup

The controller creates a private per-attempt directory, issues a256-bit capability with the existing broker's frozen `ParentScope`, and constructs `RoleSocketServer(path, broker, scope, sha256(capability))`. Construction verifies the hash's immutable grant scope exactly matches the supplied owner/project/root/attempt/generation/native session. It never accepts another otherwise-valid grant at this endpoint. Normal expiry/revocation/current parent fences remain enforced inside broker DB transactions.

A generated `client.json` contains exactly `{capability, native_session_id}`. Install it mode0400 or0440, owned by root for the default plugin, in a trusted **read-only** attempt mount at `/run/cloud-role-broker`. The plugin opens `/run/cloud-role-broker/client.json` without following its final symlink, refuses nonregular/multiple-link/writable/oversize files, and uses the fixed `/run/cloud-role-broker/socket`. The controller must protect parent paths and mount ownership: checking file mode cannot establish that a job cannot replace its directory. The default client explicitly trusts owner UID0; a separately generated trusted launcher may call `from_file(expected_owner_uid=controller_uid)` with a frozen operator-chosen UID. The JSON file and model cannot choose that UID. Thus a non-root controller with a distinct job UID must use a root-owned publication step or an explicitly pinned owner policy; the serving process itself need not run as root. No personal profile, dotenv, provider credential, platform bearer token or arbitrary endpoint is loaded. The job can steal its own attempt capability; it remains intentionally limited to that attempt's roles/actions/generation/lifetime.

The socket starts0600 with optional explicit0660 and a trusted group ID. Its directory must be owned by the serving UID and have no group/other write bit. Directory ancestors, mount policy and service accounts are trusted operator configuration; hostile ancestor races are not qualified here. Existing sockets/files are never automatically unlinked, even if stale. Accept OSErrors increment a bounded safe counter/errno and set `health().state=accept_degraded`; the loop waits50ms before retrying and recovers to serving after a successful accept. Shutdown interrupts that backoff and removes only this instance's recorded inode. Supervisors must observe this health seam; no service monitor is wired here. A real restart needs explicit controller reconciliation of stale socket ownership before recreation.

Pinned plugin bytes live under `plugins/cloud_roles`. The real `register(ctx)` registers only `cloud_request_roles` and `cloud_get_role_results`. Native `session_id` and `tool_call_id` arrive as D8 trusted dispatch kwargs. The model may supply only role/task/context_refs or request_id/cursor. Identity, capability, parent, endpoint and path fields are rejected. Native IDs still supply correlation rather than authorization; source/session stability across native restarts remains an integrated qualification gate.

## Protocol and limits

Only `POST /v1/request HTTP/1.1` and `POST /v1/result HTTP/1.1`, with one message per AF_UNIX connection, are accepted. There is no TCP listener or HTTP request forwarding. Headers must contain exactly Host localhost, Content-Type application/json, Content-Length and Connection close. Duplicate/unknown/chunked headers and duplicate JSON keys fail closed. Header cap2048 bytes, request body256KiB, response body1MiB. Client argument fields are validated before serialization, so an oversized model string/list is refused before making another serialized copy or opening a socket. Tasks still have the broker's32KiB UTF-8 cap and at most32 hash-bound context references. JSON is parsed only after the body length cap; deeply recursive/invalid/nonfinite JSON receives a fixed error. One result record means cursor must be absent/null; pagination is not falsely advertised.

The envelope contains the attempt capability, native session/call IDs and model arguments. Capabilities are sent only in the private socket request; never returned, logged or included in evidence. No access logger exists. The endpoint rejects the exact known raw capability repeated in arguments or native correlation fields before persistence, and refuses any result containing that capability; transformed/encoded forms are not claimed detectable. All handler responses use fixed code/status for known refusals and generic503 for unexpected faults, without exception text. The client representation excludes its token. This does not redact arbitrary user task text: task data is returned as the durable pending record and treated as user data.

Each connection has a single absolute monotonic deadline covering header/body reads and response writes (default server2s/client3s; max10s). There are no automatic client retransmits. A missing response reports503 (outcome may already be committed), not a bad-task400; malformed broker responses report502. The wrapper must retain the native identity when retrying an unknown outcome. Only infrastructure replay of the same actual native call uses its original identity and returns the same committed pending record; changed arguments conflict. A model-level retry with a fresh call ID is a genuinely new request and consumes budget. This transport does not reconstruct native transcripts or prevent that semantic duplication. Backend call-ID uniqueness within the frozen native session is a hard integration gate; repeated deterministic IDs across turns conflict or replay historical data. A wrapper must durably retain and replay pending native calls before returning unknown outcomes to a model. Valid bounded requests are fully read before rate refusal, so a large legitimate sender can receive429 without an early-close EPIPE. Header-stage/malformed/oversized requests may still observe a transport503 if they continue transmitting after refusal; no successful client request exceeds the enforced bounds. The server handles one request at a time with backlog8 and an attempt-wide token bucket (default10/s, burst20, configurable up to100). No thread-per-connection allocation or unbounded request queue is created. A slow client can hold its own endpoint only until its deadline. Trusted authorization callbacks must themselves be bounded: socket deadlines do not interrupt synchronous SQL/callback execution; broker SQLite busy timeout is separately bounded.

## Controller seam and remaining integration

The host-side endpoint currently invokes RoleBroker in process against the same controller DB. It has no Docker or execution methods. It is not yet the separately deployed narrow forwarder/private-controller-channel described by D4. A future process split must preserve authentication, limits, current parent fencing and commit-before-reply rather than move DB authority into job code.

`prepare` commits pending before returning. It never creates children. The trusted controller may later use `broker.admit_in_transaction(db, scope, id, SQL_only_mapping_callback)` to create role/child rows plus the mapping in one atomic transaction; the transport test proves only a synthetic SQL mapping, not real child reservation. Artifact authorization, aggregate context bounds, role policy/qualified route resolution, provider account reservation and child lifecycle remain mandatory integration work. Model arguments cannot call this seam.

The corrected fixture constructs an actual pinned `AIAgent(session_id=controller_session, ...)` with a synthetic offline client, proves its session remains unchanged, and dispatches a role request to pending. It also uses the real plugin loader and `_resolve_sequential_dispatch` from the pinned clean Hermes source and verified D8 patch overlay. Only the mount paths are substituted into a temporary directory; production plugin bytes and socket/parser/broker are unchanged. Temporary HOME/profiles, empty bundled plugins, disabled project plugins and denied TCP/DNS prevent personal/provider access. The offline model uses an explicit64KiB context and `model.ollama_num_ctx: 0`; without the latter, a localhost custom client triggers four denied local-server detection probes during constructor setup. Failed harness receipts preserve that discovery; the final setup has zero TCP/DNS attempts. This is constructor/dispatch proof, not an actual inference round trip or native CLI launch/restart proof. Evidence checks durable retry, actual-native lost-response replay, payload conflict, native/model identity failures, binder failure, concurrent retries, cancellation, expiry, revocation and size bounds. Source hashes bind the actual code used. No native transcript restart, integrated controller process restart or real job mount proof is claimed.

Host limitation: tests run on macOS under one effective UID. Owner-policy validation includes a simulated different stat UID, but actual Linux `/run` paths, read-only bind mounts, distinct controller/job UIDs, group ownership and namespace mappings remain unqualified and must pass before deployment. The scoped source fixes do not waive those gates.
