# Routed stage preparation and actual Hermes CLI checkpoint

The new `prepare_child_stage` composes the existing RoleScheduler child assignment, frozen Pstack instructions, identity-bound workspace revision and credential-free routed Hermes launch plan. It does not create another scheduler or lifecycle database. It requires a claimed preparing child, current root/account owner, live parent generation, non-revoked owner, exact frozen provider/model/effort/transport, and a trusted qualification callback binding that route to the execution digest. Nonempty context references are explicitly blocked until their controller materialization path exists; they are never silently omitted.

The child receives a new isolated copy of its assigned revision. Coding roles receive a writable copy; other current roles receive a read-only mount contract with separate `/scratch`. Preparation checks cancellation/authority before publication and again afterward. If authority changes, no prepared launch is returned; an exact identity-bound, unchanged copy is discarded before any runtime exists. Modified or replaced material remains held for explicit recovery. The launcher still must recheck admission around durable create intent and start. This checkpoint does not qualify automatic stage advancement, revision promotion, native root session bootstrap, remediation, follow-ups, or protected outcome gates.

`build_routed_launch` is separate from the historical source-only `build_launch`. It configures a named localhost custom provider, exact profile model/effort, `/v1/responses` for native Astra/Sol/Grok or the historical chat codec for the pinned Claude CLI, file tools only, empty plugins/hooks/MCP/fallbacks, no ambient provider credentials, isolated state and bounded execution. A dedicated caller capability is supplied through a protected file; it is not a provider credential. The runtime must enforce mounts, UIDs, no external network and physical cleanup. File-only capability does not yet qualify terminal-based acceptance tests.

`routed_caller` runs fixed relay/Hermes entrypoints under UID1001/1000. Detached Hermes execution has bounded stream parsing, a redacted existing public event spool and a worker-reported result marker. Raw stderr/tool outputs are not exported; absent/zero native counters remain unknown. The marker is not protected verification or physical cleanup proof. Container cleanup, relay fencing/cancellation, queue recovery and outcome acceptance remain trusted controller duties.
