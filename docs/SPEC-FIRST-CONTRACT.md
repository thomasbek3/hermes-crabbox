## 3. Immutable policy and qualification records

`BackendProfile`: id/version, runtime=hermes, source/image/adapter digests, provider, native model ID, transport, supported effort and requested effort, dedicated credential reference, endpoint policy, tool/config/skill digests, qualification receipt reference, capability set. No secret value or arbitrary URL comes from a task prompt. Editing creates a new version; old attempts retain their version.

`RolePolicy`: id/version/digest, one route for each single role, ordered route list for each panel, cross-judge pool, allowed inheritance, maximum depth/seats/attempts, bounded per-role tools, limits, enabled status. Validation rejects unknown roles/profiles, unsupported effort, unqualified dependencies and empty panels. `auto`/`inherit-parent` materializes the exact parent profile; it never triggers ambient provider discovery.

`Qualification`: exact profile/source/image/transport/auth mode and capability matrix, test receipt hashes, performed time, status and invalidation reason. A caller-supplied hash/readiness boolean is not qualification. Only the trusted qualification/activation path can bind passing evidence. Credential revocation/quarantine, config/image drift or failed required probes disables new starts; historical receipts remain immutable. In-flight revocation fences new calls and stops the affected execution under cancellation rules.

Activation uses CAS against the prior active policy/environment version. Failed candidates leave the active version unchanged. Every attempt freezes its policy; changing the default cannot silently reroute an existing task. A deliberate route change in a later turn records new provenance and uses reconstructed continuation unless exact native-state compatibility is proven.

## 5. Workflow, child and scheduler contract

Extend existing Attempts with root/parent/request/seat-ordinal/profile/revision references. Add a durable `RoleRequest` mapping and immutable `WorkspaceRevision` metadata; a RoleSeat is an identity grouping of Attempts, and RoleResult reuses the existing result manifest. Do not create a second scheduler or lifecycle store. Bind owner/project/session/turn/root attempt, policy version, parent seat, generation, request key and payload digest. Each seat has ordinal, frozen profile, input revision/context references, tool authority, reservation IDs, lifecycle/outcome and immutable result references. Unique `(parent_attempt, parent_generation, request_key)` rejects altered retries and returns the same seats for identical retries. A replacement generation cannot adopt a stale parent's request.

The trusted pstack integration exposes bounded `request_roles(role, task, context_refs)` and `get_role_results(request_id, cursor)` tools. The wrapper supplies the durable request key, not model text. Parent identity and allowed roles arrive through an attempt-scoped capability, never model text. Proposed v1 ceilings: nesting depth 2, 8 seats per request, 32 seats total per root turn, task text 32 KiB, 32 hash-bound context references, context aggregate 1 MiB. Limits are policy-visible, enforced before reservation and count failed/cancelled seats; retries cannot reset the root budget. Native Hermes delegation is disabled for this first routed workflow so it cannot bypass admission. Any later native delegation requires equivalent accounting and fences.

Every child uses the existing Attempt states/transitions from SPEC §6. Export/collection is a durable completion-intent phase, not a new lifecycle state; blocked_credentials/capacity are durable visible queue reasons. Terminal execution and verification/review outcomes remain separate. Submission reserves durable identity, not necessarily compute. Atomic launch admission checks live parent generation/cancel fence, profile readiness, writer lease, credential lease and worker/root capacity. Every coordinator, child, provider sidecar, app and verifier consumes declared CPU/RAM/PID/disk/time resources. A waiting coordinator never retains a credential lease needed by its children: finish in-flight inference and release the credential request lease before awaiting child work. Retained coordinator memory still counts. If the footprint cannot admit any child, fail readiness with required/available capacity; do not deadlock or silently discard host reserve.

Provider execution ownership is separate from session lifetime. Refreshable credentials use one trusted persistent owner and exclusive request/refresh leases, never cloned writable refresh families. Until that adapter proves safe shared access, inference requests for the identity serialize. Lease expiry alone is insufficient to release a still-running provider process: confirm termination or fence/isolate it before reassignment.

Child failure is visible to the coordinator. Required failed/missing review or verification blocks root success. Panels retain all seat outcomes and do not silently reduce the panel after failure; an explicitly configured retry creates a new attempt for the same seat within root limits and does not change model. Default automatic retry is zero for ambiguous execution; read-only reconciliation precedes any retry.

On cancel, atomically fence the root and descendants before stopping processes; deny new role calls, terminate owned tools/provider processes/verifiers, preserve partial results, release leases only after cleanup proof. Restart reconstructs the same graph and labels, reconciles pending creates/exports and never duplicates a child because a response was lost. Unknown external effects stay unknown and require the controlled integration reconciliation path. No root terminal success while a mandatory child remains unresolved or a live descendant remains unaccounted.

## 6. Files, panels, review and verification

Panel writers cannot merge to a shared branch implicitly.

Reviewer seats receive an immutable read-only revision and bounded read tools, with scratch separated from deliverable mounts. Do not call a prompt saying 'read only' an enforced boundary. Judge inputs identify every seat and its evidence, failures and omissions. Selection/grafting is a model recommendation, not verified success; selected code must be materialized and independently verified. A critical unresolved required finding yields needs_review/rejected under the declared rubric, never a blind majority pass.

### D1 — One credential topology for routed Hermes

For routed Hermes, provider credentials live only in a trusted provider-service container, never in the Hermes coordinator/worker/tool filesystem or environment. This explicitly supersedes SPEC §8's agent-mounted capsule default for new routed Hermes. The old direct-Claude capsule topology remains a historical supported execution identity, not the new workflow design. CredentialGrant gains topology, persistent-owner ID and per-request lease references; an execution-scoped grant controls whether the attempt may request inference, while a separate exclusive credential lease controls one actual provider request/refresh at a time.

One dedicated service instance owns each refreshable identity's persistent auth state. It is a narrow inference adapter, has no workspace/tools/Docker/control credentials and only the approved provider egress. It accepts an authenticated attempt-scoped inference request with frozen route and bounded messages; a caller cannot choose arbitrary model, URL or credential. It may launch the pinned unmodified provider CLI with tools disabled, or use a separately qualified native provider transport. It never executes a model-requested tool. The broker maps the provider's response to the pinned Hermes provider interface. Qualification must prove native tool IDs/transcript semantics and effective route, not merely a compatible-looking endpoint. This is a new A dependency, not an already working gateway. Broad research remains disabled until its separate data/egress gates pass.

Sequence: coordinator acquires a request lease through the service → service performs inference using its sole auth store → service completes/cleans up the request and releases that lease → Hermes receives a role tool call and submits it without a provider lease → admitted child requests inference from the same service → service serializes the child's request/refresh → child executes tools outside the credential boundary → provider lease releases between inference calls. A coordinator waiting on child completion holds no credential request lease. Service crash quarantines uncertain refresh state; no second owner starts until the previous process is confirmed gone/fenced. Execution grants and credentials are independently revoked on cancellation.

### D2 — Admission and time budgets

At the initial two-slot configuration, only one root workflow runs at a time. Root admission atomically reserves a coordinator envelope AND one child execution envelope. A second root stays queued; child admission consumes the root's already reserved child slot rather than competing with another root. Panel seats serialize in that child slot; independent work does not imply concurrent launch. The child can finish tool/model work and release its slot before a later review/synthesis/verifier. All nested roles in the initial profile are leaf executions; no running leaf may await another compute child. A nested request is returned to the root scheduler for flattening or rejected with nesting_unsupported, never held while occupying the only child slot. Configured maximum nesting 2 does not promise simultaneous nested coordinators.

Each envelope defaults to 2 CPU / 4 GiB RAM / 512 PIDs inclusive of an active provider service allocation: reserve up to 0.5 CPU / 1 GiB / 128 PIDs within the active caller's envelope for the provider component; the Hermes component gets the remainder. The provider component is stopped when idle for the initial profile, retaining only private auth state, or its measured idle resources remain explicitly charged to the root reservation. It cannot remain running unaccounted after root cleanup. Existing host floors and quota/log caps still apply; readiness may require larger configured envelopes if real measured startup cannot fit, never silently exceed them. The two reserved envelopes are disjoint and total 4 CPU / 8 GiB RAM; provider allocation is not added twice. Verifier/app/preview footprints use the same declared reservation or separately admitted envelopes, never hidden sidecars.

Root wall-clock budget defaults to four hours starting at admission, includes child waits and does not pause. Each leaf retains the existing one-hour execution and ten-minute preparation maxima, clamped to remaining root time. Queue time before root admission is tracked separately. Root timeout fences all descendants exactly like cancellation with reason root_budget_exceeded. Role reservation checks remaining root time; zero-time seats never launch. These are defaults to measure, not a promise that all 32 allowed seats can finish in one turn.

If the coordinator container disappears and exact native continuation is unqualified, mark its attempt interrupted, fence/stop descendants, retain completed revisions/results and require an explicit reconstructed follow-up/new attempt. Controller restart with the original coordinator still alive may reconnect only under matching generation and runtime identity. No automatic replay of the coordinator prompt.

### D4 — Broker channel, idempotency and external reads

Expose a per-attempt Unix-domain socket at /run/cloud-role-broker/socket, mounted only into that attempt with no broader host directory. A worker-owned narrow broker serves bounded HTTP over this socket, without Docker/control operations. It forwards validated role requests through its own private controller channel. No new job-to-host network exception or platform bearer token is needed. The broker cannot trust container UID alone: use a random 256-bit attempt capability stored hashed by the controller, bound to owner/project/root/attempt/generation, allowed role/tool actions and expiry. The raw capability is a stealable in-attempt authority limited to that scope; do not claim it is secret from job code. No arbitrary parent/owner/profile/endpoint fields are accepted. Every request rechecks cancellation/revocation/generation; response bodies are bounded to 1 MiB and paginated.

Private broker routes: POST /role-requests and GET /role-requests/{id}?cursor=... . The wrapper derives its idempotency key from the immutable parent attempt/generation, persisted native session ID and native tool-call ID; bind the canonical tool name/argument digest. Before transmission, fsync a controller-owned pending-call record through the broker. Retry of the same native tool call reuses that key; changed payload returns409. Missing/unstable native tool-call IDs fail the role-call capability probe instead of substituting a new random key on every retry. Equivalent prompts in genuinely new tool calls are new requests and count against the root seat budget. A native transcript replay never silently changes the attempt/generation.

Public authenticated API additions: GET /sessions/{id}/workflow (paginated request/seat/attempt edges and outcomes), GET /attempts/{id}/route (safe frozen/effective route and trust labels), GET /role-policies (authorized redacted configured policies/readiness). Existing observe/project ownership checks apply; guessed IDs cannot disclose another owner. CLI `show --workflow` and dashboard child timeline consume these routes. Activation remains an administer-scoped CAS operation with environment/qualification receipts; model output and job capabilities cannot activate policies.

### D6 — Revision ownership and follow-up

Root coordinator workspace is a read-only immutable input revision with separate private scratch. It cannot mutate the canonical session working tree. An implementation seat gets an isolated writable snapshot of that revision; after it stops, the worker safely exports/hashes a candidate WorkspaceRevision using the existing artifact/completion-intent path. No worker-supplied Git hook/filter executes on the host. Review mounts that exact candidate read-only; failures lead to a new bounded coding attempt based on that candidate, not mutation under an active reviewer.

When several candidates exist, synthesis gets an isolated writable snapshot of the chosen base plus hash-bound candidate artifacts; it outputs another immutable candidate. The controller's existing protected verifier runs against the chosen final candidate. On mandatory checks passing, a transaction CAS-promotes that candidate as the session delivered revision, binding the root result and child evidence. Stale expected base rejects promotion. Failed/incomplete review or verifier never changes the last delivered revision; partial candidates remain retrievable under explicit labels. A root with no code change may deliver a reviewed document artifact under its own rubric.

A reconstructed follow-up starts a new root attempt from the last delivered revision (or an explicitly selected partial candidate), with original goal, current acceptance criteria, safe summary, unresolved findings and hash-bound artifacts. It states cold context; never copies provider auth, native hidden state or unrelated child transcripts. Each turn records its exact base revision and policy. The canonical session pointer is controller-owned metadata; it is not a shared writable mount across parents/children.
