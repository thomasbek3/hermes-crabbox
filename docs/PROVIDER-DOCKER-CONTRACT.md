# D9 concrete Docker adapter checkpoint

`ProviderDocker` is controller-only and implements the existing `ProviderDispatch` runtime callbacks and `ProviderLeases` cleanup verifier. It does not activate the worker, register accounts, select a user account, read provider credentials, start an HTTP listener or migrate a database. The owning dispatcher must hold its account flock around callbacks; calling these internal methods is not public authentication. Real provider/auth qualification remains separate.

`DockerConfig` freezes the full local image ID, raw readonly profile-file SHA256, canonical five-field pinned-profile digest, approved credential path, private staging root, exact domain tuple and provider identity958:959. The adapter uses the shared profile_binding helper and validates the parsed profile before launch. The root-owned profile must be readable by the provider without group/world write; the credential is validated by metadata only (regular, one link, <=4096 bytes, no world/group-write access, provider-readable). The controller never opens that credential. The approved canonical credential's actual host ownership still belongs in the activation receipt. This module does not select a credential from a request or copy it into a new token file.

The real Docker CLI is forced to `unix:///var/run/docker.sock`, an empty private CLI config directory and a minimal environment. Ambient Docker contexts, registry config, proxy variables and HOME are excluded. Command arguments use argv only. Combined stdout/stderr is capped, the command deadline is enforced, CLI process groups are killed/reaped on timeout, and stderr never becomes a user error. Killing the CLI does not establish that its daemon operation failed or its container stopped.

## Creation, execution and resource policy

Create first persists a versioned empty journal before writing the transcript or running Docker preflight. Client and server must report stable Docker28+ versions, and their versions enter the journal. Create writes the bounded transcript to a private controller staging file, mode0640/group959, then mounts it readonly. A constant Python wrapper opens it as stdin and execs provider_main with a fixed profile path and explicit private numeric proxy argument. No transcript, credential or model-selected command appears in argv. Raw staged transcripts are deleted after verified request cleanup; private journals remain for reconciliation/audit. Retention of completed journal directories is a separate gate.

Create makes exactly four resources, all stopped at return: internal isolated bridge, external bridge, gateway container and provider container. The internal bridge requires Docker isolated gateway mode for both IP versions; no fallback is allowed. Gateway address is derived from verified private IPv4 IPAM. Gateway connects to both networks before start but has no token/profile/transcript mount and cannot forward IP packets. Provider joins only the internal network and gets an unusable external DNS setting; its only approved outward path is public-only allowlisted CONNECT through the numeric gateway.

Provider limits:0.4 CPU,960MiB memory/swap ceiling,112 PIDs, nonroot958:959, read-only root, dropped capabilities, no-new-privileges, private IPC and private256MiB noexec/nosuid/nodev tmpfs. Gateway:0.1 CPU,64MiB memory/swap,16 PIDs,65534:65534, same privilege restrictions and16MiB tmpfs. Docker local logs use1MiB times2 files. No host ports are published. The image must explicitly contain the reviewed egress module; the old runtime helper that starts a gateway during create is not reused.

Inspection checks all four full IDs, names, ownership labels, immutable image, resource limits, privileges, mount sources/destinations/readonly flags, network attachment set, forwarding settings, network peer ownership, exact command, DNS, tmpfs options, bounded logging and disabled restart policy. Mount parents must be controller/root-owned without group/world write, except a root-owned sticky ancestor such as /tmp. Docker automatically inherits image labels; only labels read from that exact immutable image may accompany the exact request labels. Image labels in the provider ownership namespace (or legacy cloudd namespace) are rejected. After validating the complete label set, observations return the exact request labels to D9. Stopped Docker endpoints can report blank NetworkID; their exact configured network names are checked, and other attachments are refused.

Start separately acknowledges the gateway start, polls readiness within10 seconds using a static Bash builtin TCP probe (no request interpolation), rechecks cancellation, acknowledges the provider start, then bounds execution by the caller's remaining execution deadline (maximum120 seconds from D9 admission). It never spends120 seconds in collect. Collect is a separate maximum5-second bounded log transfer after provider exit; it returns the provider main structured envelope, including structured failure envelopes. Provider protocol interpretation remains the executor's duty. Cancellation is checked between startup stages and during execution; acknowledged provider execution is stopped with a one-second grace and retained for exact cleanup. Execution timeout also stops the provider before returning; the stop has its own bounded five-second grace budget after the execution deadline. An unanswered stop remains unknown and never authorizes reuse. Docker RPCs are individually capped at5 seconds; total callback deadlines and safe retained ownership take precedence over trying indefinitely.

## Durable effects and cleanup

Each mutating Docker call has a private fsynced intent before the RPC and an acknowledgment after success. The journal binds reservation/epoch, request, attempt/generation, launch, profile and payload digest. Missing objects never substitute for an unanswered RPC. A trusted command runner distinguishes failures before process spawn and clears pending only for that proven no-RPC case. Any other pending journal RPC makes resolve and cleanup refuse; a daemon timeout therefore retains ownership. Operational reconciliation of an unanswered RPC remains a separate administrator/trusted-fencing gate; this adapter never restarts Docker or prunes shared resources.

A safe stale journal.next (regular, private, controller-owned and single-link) is removed before a new atomic save; unsafe temporaries are refused. Missing or corrupt initial journals and pre-journal filesystem/preflight failures remain conservatively held, not interpreted as no effects. Acknowledged complete creation can be rebound after a controller crash. A partial create with only acknowledged effects can be cleaned by its exact journal IDs. Partial acknowledged start can similarly be cleaned. Acknowledged started execution can be resolved and subsequently stopped/removed under the dispatcher cleanup receipt. Reconciliation never replays a prompt. Successful removal IDs are persisted atomically with their RPC acknowledgment; a later cleanup may skip only those exact acknowledged removals. Every remaining object must still match its immutable ownership identity. Cleanup removes provider and gateway before their two networks, within a20-second callback budget. Failure retains the ledger lease; no response is released by this adapter itself.

The cleanup callback accepts an empty logical-owner scope only when the trusted lease layer supplies request_id=None and no outstanding dispatches after its durable freeze. This is an internal no-outstanding-work ledger assertion, not permission to accept a blank model-provided target. Unsupported refresh leases with an outstanding request but no dispatch are refused. Actual container/cgroup destruction is still required for every created request; process-group-only cleanup never authorizes credential reuse.
